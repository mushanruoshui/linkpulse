数据流的编号，名称，默认去向:
    0 , stdin , 通向键盘
    1 , stdout , 通向终端屏幕 
    2 , dtderr , 通向终端屏幕 

> 和 >> 的区别,哪个有覆盖风险:
    > 指令对文件操作,将指令覆盖写入指定文件,有覆盖风险
    >> 指令对文件操作,将指令追加写入指定文件,无覆盖风险
    > 和>>的区别在于指令写入文件处理方式的不同，即对指定文件原本内容的处理方式是清除还是保留

2>&1 为什么重要:
    2>&1这个重定向写法代表2通道重定向到1通道的所在地,这代表了在执行到此时1通道必须已经确定，否则操作将会失败，这也决定了2>&1是重定向写法中唯一需要注意编写顺序的写法

为什么 cmd > file 2>&1 和 cmd 2>&1 > file 结果不同:
    cmd > file 2>&1 是正确写法,1通道正确以覆盖写方式指向目标文件后，2通道根据2>&1指令正确指向1通道所在地，即目标文件所在地
    cmd 2>&1 > file 是错误写法,2通道在1通道并未指向目标文件时指向了1通道的所在地(而此时1通道的所在地仍然是默认的命令行屏幕),此时只有1通道正确指向目标文件所在地,2通道仍然指向命令行屏幕

逐段解释 pip install -r requirements.txt 2>&1 | tail -40:
    1.管道建立: | 将pip install -r requirements.txt 2>&1 指令的1通道指向tail -40 的0通道
    2.1第一段指令前半部:pip install -r requirements.txt: 读取txt文件中的内容,用pip指令安装文件中扩展
    2.2第一段指令后半部:2>&1: 2通道根据2>&1指令正确指向1通道所在地，即第二段指令0通道
    3.第二段指令执行:tial -40:0通道接收前指令1通道与0通道内容,将倒数40行输出到默认的命令行屏幕
